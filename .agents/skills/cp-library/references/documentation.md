# 文書指針

同名 Markdown は、後で使うための索引とメモにする。既存の説明を直す場合は変更に関係する箇所を更新し、無関係な節の書き直しを広げない。

## 同名 Markdown

新規作成では次の構成を使う。

- **Summary**: 何をするか、重要な入力前提、注意点を短く書く。
- **Functions または Snippet**: 関数・クラスなら API の入出力と計算量を示す。スニペットなら貼るコード、必要な変数・判定関数、最終的に得られる変数、計算量を示す。
- **Usage**: 最小の使用例を載せる。入力列と、重複除去後の補助配列などの派生データを区別する。スニペットに import 前提の API 説明を当てはめない。
- **References**: 実際に参考にした資料へのリンクと、何を参考にしたかを書く。参照していない資料を調査済みとして載せない。
- **Related**: 関連する AtCoder の問題名・問題 URL と、実在する自分の解答への相対リンクを載せる。ABC に限定しない。該当する問題や解答が見つからなければ、その旨を記し、リンクを捏造しない。

自分の解答へのリンクは、この Markdown から辿れる相対パスにする。例えば `library/graph/<name>.md` からは `../../src/abc456/e.py` を使う。

## README

`library/<category>/README.md` は簡単な目次として保つ。新規追加や名前・配置の変更時は、実装と説明へ辿れるよう更新する。カテゴリの追加・変更時には `library/README.md` も揃える。
