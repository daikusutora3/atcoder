# 競プロライブラリ

`library/` を、提出に貼りやすく、後で探して再利用しやすい形に整える。

## 作業に応じて読む

- **探す・再利用する**: 分類が分かれば対象カテゴリを検索し、候補の `.py` と同名 `.md` で入出力・前提・計算量を確認する。分類が不明なら `library/README.md` を入口にする。既存実装で足りる場合はそれを使う。
- **追加・一般化・動作変更する**: [実装指針](references/implementation.md) を読む。既存候補と必要な参照元の `src/...` を確認し、再利用する部分を切り出す。
- **説明・索引を整える**: [文書指針](references/documentation.md) を読む。新規追加や API・前提・計算量を変える作業でも参照する。

対象が分かっている軽微な修正では、そのファイルと変更に関係する説明を確認すればよい。

## 判断と完了条件

- 問題固有の処理は `src/...` に残し、ユーザーが求める再利用部分だけを `library/` に置く。
- 明示された関数数・スニペット形式・編集範囲を優先する。依頼に必要な設計やローカルでの確認は、その範囲内で進める。
- 新規追加は実装、同名 Markdown、カテゴリの README を揃える。カテゴリを増やした場合は `library/README.md` も更新する。
- 動作を変えた場合は、前提に合う使用例と重要な境界ケースを確認し、変更に起因する不具合を直す。文言修正だけなら動作テストを増やす必要はない。
- 再利用の依頼は、選んだ実装が制約に合うことと使い方が示せた時点で完了する。変更の依頼は、対象の実装・説明・索引が整合し、必要な確認が済むまで進める。

結果は、再利用先または変更ファイルと確認結果を簡潔に伝える。API・計算量・参考資料は、選択や変更の理解に必要なものだけ添える。
